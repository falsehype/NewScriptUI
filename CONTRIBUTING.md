# Contributing to NewScriptUI

Thanks for helping improve NewScriptUI.

## Before opening an issue

- Check existing issues for duplicates.
- Use the bug or feature-request template.
- Include a concise title and reproducible steps.
- Include screenshots or short clips when they make a visual issue clearer.
- Remove usernames and other private information from attachments.

## Pull requests

1. Keep changes focused and explain the reason for the change.
2. Preserve the existing dark visual language unless the change concerns theming.
3. Keep the README, roadmap, API status, and changelog in sync with the code.
4. Do not claim support for behavior that has not been tested.
5. Include a clear manual test checklist in the pull request description.

## Style

- Use readable Luau and descriptive names.
- Prefer small functions with clear responsibilities.
- Avoid duplicate global input listeners.
- Clean up event connections, tweens, and temporary instances when destroying UI.
- Explain any new dependencies.
